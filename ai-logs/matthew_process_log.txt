PROMPT 2:
"How do I set up axios to automatically attach JWT tokens to every request?"

AI RESPONSE SUMMARY:
- Create axios instance with axios.create()
- Use interceptors to add Authorization header before each request
- Store token in localStorage or sessionStorage
- All API calls use this instance instead of raw axios

WHAT I LEARNED:
- Axios interceptors run before every request automatically
- Centralizing auth logic means you only write it once
- baseURL in axios.create() sets the default server URL

CODE SNIPPET USED:
```javascript
const api = axios.create({
  baseURL: "http://localhost:8080",
});
api.interceptors.request.use((config) => {
  const token = localStorage.getItem("token") || sessionStorage.getItem("token");
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});
```

PROMPT 3:
"How do I replace mock data with real API calls in my React components
and handle loading and error states?"

AI RESPONSE SUMMARY:
- Use useEffect hook to fetch data when component mounts
- Store data in useState, initialize as empty array or null
- Add separate loading and error states
- Handle errors in .catch() block

WHAT I LEARNED:
- useEffect with empty dependency array [] runs once on mount
- Always handle loading and error states for better UX
- API calls are asynchronous so data won't be available immediately

CODE SNIPPET USED:
```jsx
const [playlists, setPlaylists] = useState([]);
const [loading, setLoading] = useState(true);
const [error, setError] = useState('');

useEffect(() => {
  api.get('/api/playlists/library')
    .then(res => {
      setPlaylists(res.data);
      setLoading(false);
    })
    .catch(() => {
      setError('Could not load your library. Please try again.');
      setLoading(false);
    });
}, []);
```

ISSUES ENCOUNTERED:

HOW I FIXED IT:

- Changed songCount vs trackCount, and mood object vs mood string

SESSION 5: Git and Project Collaboration

PROMPT 7:
"How do I push my frontend code to a specific branch on a shared GitHub repo
without affecting other teammates' branches?"

AI RESPONSE SUMMARY:
- Use git checkout -b to create and switch to new branch
- Always push to your own branch with git push origin branch-name
- Never push directly to main
- Use git fetch and git pull to get teammates' changes

WHAT I LEARNED:
- Each teammate works on their own branch to avoid conflicts
- Force push (--force) needed when rewriting branch history
- Git merge --abort cancels a merge with conflicts

CODE SNIPPET USED:
```bash
git checkout -b matthew/frontend-library-social
git add .
git commit -m "Add library and social UI pages"
git push origin matthew/frontend-library-social
```

ISSUES ENCOUNTERED:
- Accidentally created embedded git repository (submodule) inside project folder
- node_modules folder was being tracked by git

HOW I FIXED IT:
- Removed embedded .git folder with Remove-Item -Recurse -Force
- Added node_modules/ to .gitignore and ran git rm -r --cached
